# 計算量の目安

迷ったら**掛け算して数字を出す**。`log` の個数で判断しない。

## 2秒で通るか

```
1e8 以下      ほぼ通る
1e8 〜 1e9    中身しだい。配列アクセスだけなら通る
1e9 超        落ちる
```

## 式ごとの値

| | n=1e3 | n=1e4 | n=1e5 | n=2e5 | n=1e6 |
| --- | --- | --- | --- | --- | --- |
| `n log n` | 1e4 | 1.3e5 | 2e6 | 4e6 | 2e7 |
| `n log^2 n` | 1e5 | 2e6 | 2.8e7 | 6.2e7 | 4e8 |
| `n sqrt(n)` | 3e4 | 1e6 | 3.2e7 | 8.9e7 | 1e9 |
| `n log^3 n` | 1e6 | 2.3e7 | 4.6e8 | 1.1e9 | 7.9e9 |
| `n^2` | 1e6 | 1e8 | 1e10 | 4e10 | - |
| `n^2 log n` | 1e7 | 1.3e9 | - | - | - |

`n = 2e5` なら `n log^2 n` は 6200万。**log 2つは普通に通る**。
`log` を1つに落とす必要があるのは `n log^3 n` から。

## 1回の重さ

同じ「1回」でも 30 倍くらい違う。上の数字に掛ける。

```
配列アクセス・四則演算      1
セグ木のクエリ1回           log n 回ぶんの軽い操作
unordered_map の1操作       10
map / set の1操作           30（log n も別に掛かる）
再帰呼び出し                 2〜3
```

`n log n` でも中身が `map` なら `n log^2 n` の配列版より遅い。
