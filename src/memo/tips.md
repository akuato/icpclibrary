# 考察 tips

詰まったら上から順に。「→」の先を自分に聞く。

## 読んだ直後

- 自明に見える → 制約の一文を読み落としていないか
- 「解が存在するように入力が選ばれる」 → 解なし判定は不要。構造が緩い
- 端数・実数が許される → 貪欲でよい合図。整数なら NP 困難のことが多い
- 「条件を満たすものを1つ」 → 構築。考えずに実験へ
- 状態が時間で変わる → 各状態の**始まりと終わりを両方**書く。
  終わりが空欄なら永続。from then on / 以後ずっと は飛ばしやすい

## 手が止まったとき

- 良い性質が見えない → **実は状態数が少ないのでは？**
- 構築問題 → 小さいケースの答えを全部並べる。1つではなく全部
- 未知の定数・係数がある → 全探索の答えに合わせて決める
- 候補が多すぎる → 鳩の巣。どれか1つは必ず残らないか
- 候補が絞れた → そこで得た情報を全部使ったか。値だけでなく位置も
- 効く制約が1〜2本 → 貪欲。交換レート（コスト ÷ 消費する資源）の順
- 答えに上限がある → その上限で打ち切れないか
- 2つの量が単調 → 片方を反転して向きを揃えられないか

- 「ちょうど◯◯」を数えたい → 下界か上界を示して「最小値/最大値
  の個数」「しきい値以上の個数」に言い換える。場合分けが消える
- 条件が複数あるとき → 「要素を減らしても壊れないもの」と
  「そうでないもの」に分ける。前者は尺取りで窓を決め、
  後者を窓の中で数える

- 答えを決め打つと簡単になる → リセットできる期待値は X を仮置きして
  F(X) = X の交点を二分探索。傾き = リセット到達確率 < 1 なので交点は一意
- k が巨大なコイン／個数問題 → 最良比（a_i / i が最小）の品を1つ決める。
  残りは鳩の巣で**合計 id-1 個以下** → N = n^2+100 まで dp して外挿
- 構築で存在が保証されている → 1手で1しか変わらない量を探して中間値の定理。
  DFS の「未訪問 / スタック上 / 完了」の3分割など
- ダイクストラで補助量（速度・燃料など）を持つ → pop は時刻の昇順なので、
  先に pop した方が時刻では必ず勝っている。パレート集合は不要で best[v] 1本で
  枝刈りできる。条件は単調性（補助量が良いほど以後も悪くならない）

## 期待値・確率

- 絶対値 / min / max が出た → 期待値の外に出せない
- 「○○を固定すると」 → その状況が起きる確率を掛けたか
- 整数の格子 + 連続の揺らぎ → 距離 0 のときだけ別扱い
- 全体の状況が個体の行動に影響する → その量は決定的か。
  「無限人」「十分多い」は決定的の合図（平均場）。1個体の
  分布だけ持てばよい。有限だと個体どうしが相関して詰む

## インタラクティブ

- 実数が返ってくる → **0 と比較しない**。真の値のギャップを
  計算して、その 1/10 くらいを閾値にする
- 整数座標しか指定できない → 斜めに引けば実質的に小数位置を
  探れる。接するケースが消えて境界が綺麗に切れる
- max / min にまとめられて返る → 他の成分はノイズ。1つだけ
  振るなら、**他は端ではなく中央に固定**してノイズ床を下げる
- クエリ上限がある → 実際に数える。上限ちょうどは危ない

## ゲーム

- スコアを最適化するゲーム → 答えを二分探索して **01 の勝敗ゲーム**に落とす
- 木のゲーム → dp[v][先手が誰か] = 勝者。この値は普通3種しか出ない：
  常にA勝ち / 先手勝ち / 常にB勝ち。+1 / 0 / -1 に潰すと
  遷移が「子の票の和の符号」になる
- **先手勝ち（0）は中立で0票**。どちらも1手で自分の符号に倒せるから
- 勝敗2値のまま数えて合わないときは、第三の状態を疑う
- 最適手は「-1 の子を丸ごと消す」。ただし子が全部 0 なら消しても票が動かず
  手番を失うだけ。符号の決まった子を持つ頂点まで降りてから消す
- 「一番上を消せば良い」「一番大きいのを消せば良い」は、この降下が要る局面で破れる

## 実験

- 支配関係（この手は無意味 / この手に劣る）を思いついたら、
  **全探索と照合するまで提出しない**。状態をビットマスクにして
  f(mask, turn) の min/max メモ化、合法手が無ければ終局。書くのに5分
- 入力側も全列挙する。木なら p[i] < i の全パターン、n=8 で 5040 通り
- 値域は「破れそうな最小」を超えて取る。木なら n = 8〜9、数列なら長さ 8〜10。
  n <= 6 だと嘘が隠れる（APAC 2026 B は n=7 で初めて破れた）
- ビット・符号・境界を必ず混ぜる

## 重い・通らない

- log が増えて怯んだ → 捨てる前に掛け算する。n = 2e5 なら
  log 2つで 6200万、普通に通る。落とすのは log 3つから。
  表は memo/complexity.md
- オーダーは足りているのに遅い → 情報を落としている
- アクセスが 10^8 超 → 連続かランダムか。連続 10^9/秒、ランダム 10^8/秒
- 内側がランダムアクセス → 連続にできないか
- キーで引いている → 配列の添字にできないか
- メモリが足りない → **次元を使い回せないか**。dp[i][j][k] の i は
  2 枚で足りることが多い
- まだ足りない → 型を落とす / グローバル生配列 / フラット化

## 出す前

- 置いた定数の根拠を1行で言えるか
- 最悪ケースを自分で作って測ったか
- デバッグ出力を消したか
