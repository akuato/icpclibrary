# メモリと配置

すべて手元（Ubuntu 24.04 / g++ 13 / x86_64）での実測値。

## 型ごとのバイト数

| 型 | バイト | 1024MB で持てる個数 |
| --- | --- | --- |
| `vector<bool>` / `bitset` | 1 bit | 約 8×10⁹ |
| `char` / `bool` | 1 | 約 10⁹ |
| `short` | 2 | 約 5×10⁸ |
| `int` / `float` | 4 | 約 2.5×10⁸ |
| `ll` / `double` / `pair<int,int>` / ポインタ | 8 | 約 1.25×10⁸ |
| `i128` | 16 | 約 6×10⁷ |
| `set` / `map` の1要素 | 約 40 | — |
| `unordered_set` / `unordered_map` の1要素 | 約 32 | — |

`reserve` 無しの `push_back` はピークが最大2.5倍。

## グローバル生配列は触った分だけ課金される

381 MiB を確保して、先頭だけ書き込んだときの実メモリ。

| 触った量 | グローバル生配列 | `vector` |
| --- | --- | --- |
| 1 MiB | **1.0 MB** | 381.5 MB |
| 95 MiB | **95.4 MB** | 381.5 MB |
| 381 MiB | 381.5 MB | 381.5 MB |

`vector<T> v(n)` は構築時に全要素をゼロで埋めるので、その場で
全ページに触る。グローバル配列は BSS に置かれ、OS が書き込んだ
ページだけを割り当てる。

**大きく取って一部しか使わないならグローバル生配列**。サイズが
実行時に決まる、関数内で持つ、`push_back` で伸ばすなら `vector`。

## vector<vector<>> は1行あたり約38バイト

`vector` 本体 24 バイト + `malloc` のヘッダ等。

| 形 | 理論値 | `vv` | フラット |
| --- | --- | --- | --- |
| 1000 × 1000 | 3.8 MB | 3.9 MB | 3.9 MB |
| 100000 × 100 | 38.1 MB | 42.0 MB | 38.1 MB |
| **2000000 × 4** | 30.5 MB | **106.9 MB** | **30.5 MB** |

判断は `行数 × 38 バイト` が無視できるかだけ。1行が数要素しか
ないときは必ずフラットにして添字を自分で計算する。

## deque は空でも約656バイト

| | 空 | 1個入り |
| --- | --- | --- |
| `vector` を100万個 | 22.9 MB | 53.4 MB |
| `deque` を100万個 | **656.1 MB** | 656.1 MB |

空でも 512 バイトのノードを確保するため。1個なら誤差だが、
10⁵ 個以上並べるなら `vector` にする。中身が入っていれば
メモリはほぼ同じ（10⁷ 要素で 83.6 対 79.8 MB）。

## vector<bool> は1bitだが遅い

4×10⁸ 要素で測ると

| | メモリ | 書き込み+読み出し1往復 |
| --- | --- | --- |
| `vector<bool>` | 48 MB | 1.17 s |
| `vector<char>` | 384 MB | **0.21 s** |

1要素ごとにシフトとマスクが入るので 5.6 倍遅い。メモリに余裕
があるなら `char`。

## アクセスの速さは配列サイズではなくパターンで決まる

2×10⁸ 回アクセスしたときの速度。

| 配列サイズ | 連続 | ランダム |
| --- | --- | --- |
| 256KB | 3243 M/s | 2257 M/s |
| 4MB | 2418 M/s | 444 M/s |
| 32MB | 2581 M/s | **152 M/s** |
| 512MB | 1243 M/s | **40 M/s** |

**連続アクセスは配列サイズにほぼ依存しない。** ランダムは
キャッシュに収まるかで決まる。見積もりは

```
連続    10^9 回/秒
ランダム 10^8 回/秒（キャッシュ外）
```

計算量だけでなく「ランダムアクセスが何回か」を数える。

## bitDP はフラグを整数に詰める

`bool ok[n][1<<n]` のように「状態ごとに n 個のフラグ」を持つと、
`ok[v][bit]` が 16 MB 飛びになってキャッシュが効かない。
n ≤ 32 なら `int` 1個に詰める。

```cpp
int ok[1 << 24];              // ok[bit] の v ビット目がフラグ
ok[bit] |= 1 << v;            // 構築
int m = ok[bit] & ~bit;       // 使うとき
while(m) {
   int v = __builtin_ctz(m);
   m &= m - 1;
}
```

n = 24、2²⁴ 状態で測ると

| 配置 | 時間 | メモリ |
| --- | --- | --- |
| `ok[v][bit]`（16MB飛び） | 2.39 s | 384 MiB |
| `ok[bit][v]`（連続） | 2.02 s | 384 MiB |
| **`int` に詰める** | **0.28 s** | **64 MiB** |

メモリ6分の1、速度8.5倍。添字の入れ替えだけでは効かない。
n ≤ 64 なら `ll`、それ以上なら `bitset` の行を持つ。
